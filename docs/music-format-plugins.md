# Music format plug-in architecture

## Purpose

`simple`, `player`, and `editor` must not implement source-format detection separately.
Every supported source format is registered through `plugins/music-format-core.js`, converted to a standard MIDI file, and then passed to the existing MIDI analysis, preview, MML conversion, and editor import paths.

The common conversion result is always a Standard MIDI File beginning with `MThd`.

## Load order

All three pages load scripts in this order:

1. Existing low-level converters required by wrappers
   - `musicxml-to-midi.js`
   - `pako_inflate.min.js`
   - `finale-mus-to-midi.js`
   - `midi-to-mml.js` where needed
2. `plugins/music-format-core.js`
3. One `plugins/format-*.js` registration script per format or extension
4. Shared parser helpers, before the wrappers that use them
   - `plugins/guitarpro-local.js`
   - `plugins/vocal-format-parsers.js`
5. `plugins/supported-files-ui.js`
6. The page application script

Do not add a new format only to one page. Register it in the common plug-in layer and load the same script from all three pages.

## Supported formats

### Core music files

| Plug-in | Extensions | Notes |
|---|---|---|
| `format-midi.js` | `.mid`, `.midi` | Standard MIDI and MIDI wrapped in a 128-byte MacBinary container |
| `format-musicxml.js` | `.musicxml`, `.xml`, `.mxl` | MusicXML and compressed MusicXML |
| `format-finale-mus.js` | `.mus` | Finale, NotePad, and PrintMusic 2001–2005 ENIGMA BINARY files; not DOOM MUS or MUSX |

### Tablature

| Plug-in | Extensions | Notes |
|---|---|---|
| `format-gp3.js` | `.gp3` | 로컬 Guitar Pro 3 파서 |
| `format-gp5.js` | `.gp5` | 로컬 Guitar Pro 5 파서 |
| `format-tab.js` | `.tab` | Text guitar/bass tab; timing is estimated from character spacing |

Guitar Pro 3/5 conversion uses parser files bundled under `plugins/vendor`; no CDN or runtime network request is used. GP4, GPX, and modern `.gp` are intentionally not advertised until an equally offline, verified parser is bundled. String/fret positions and playing techniques that MIDI/MML cannot represent are simplified.

Power Tab `.ptb` is not included in this build.

### Vocal sequencer projects

| Plug-in | Extensions | Notes |
|---|---|---|
| `format-vsq.js` | `.vsq` | VOCALOID2 MIDI-based sequence |
| `format-vsqx.js` | `.vsqx` | VOCALOID3/4 XML project |
| `format-vpr.js` | `.vpr` | VOCALOID5/6 ZIP/JSON project |
| `format-ust.js` | `.ust` | UTAU text sequence |
| `format-ustx.js` | `.ustx` | OpenUtau YAML project |
| `format-svp.js` | `.svp` | Synthesizer V Studio JSON project |
| `format-s5p.js` | `.s5p` | Early Synthesizer V JSON project |
| `format-ccs.js` | `.ccs` | CeVIO Creative Studio XML project |

The common parser is `plugins/vocal-format-parsers.js`. Notes, tracks, tempo, and time signatures are retained when those values can be identified. Voicebanks, phoneme timing, detailed pitch curves, dynamics, AI expression, and program-specific data are not preserved in MIDI/MML.

DeepVocal `.dv`, Piapro Studio `.ppsf`, and VoiSona `.tssln` are not included in this build.

## Registry API

The global registry is `window.MabiMusicFormats`.

- `registerFormat(definition)` registers one format.
- `findFormat(fileName, mimeType, bytes)` finds a format by extension, MIME type, or optional detector.
- `isSupported(fileName, mimeType)` checks whether the registry accepts a file.
- `convertBytes(bytes, fileName, mimeType, options)` returns `{ midiBytes, format, sourceType, sourceLabel, metadata }`.
- `convertFile(file, options)` reads a browser `File` and converts it.
- `supportedExtensions()` returns all registered extensions.
- `listFormats()` supplies the supported-files popup.

A registration must provide a stable `id`, display `label`, `category`, one or more `extensions`, and a `convert()` function. The converter must return either MIDI bytes or `{ midiBytes, metadata }`.

## Adding another format

1. Add `plugins/format-<name>.js`.
2. Put reusable heavy parsing logic in a clearly named helper under `plugins/` when multiple extensions share the same structure.
3. Register the format through `MabiMusicFormats.registerFormat()`.
4. Load it in `simple/index.html`, `player/index.html`, and `editor/index.html` in dependency order.
5. Mark relevant inputs with `data-music-format-input`. `supported-files-ui.js` merges the live registry extensions into their `accept` values, while the static HTML list remains a no-script fallback.
6. Do not claim support in the popup until conversion works.
7. Add a minimal fixture and case to `tools/test-music-format-plugins.js`.
8. Confirm the generated bytes start with `MThd` and pass the existing `MabiMidi` parser/MML converter.

## Regression tests

Run from the project root:

```bash
node tools/test-music-format-plugins.js
```

The test covers format registration, extension detection, representative TAB/vocal fixtures, MIDI output validity, MacBinary MIDI/VSQ normalization, and conversion through the existing MML engine.

Legacy Finale MUS can also be checked with:

```bash
node tools/test-finale-mus.js path/to/file.mus
```

The sample source files used for manual cross-checks are intentionally not bundled with the project.
